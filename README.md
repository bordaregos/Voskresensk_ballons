# Генератор заключений на баллоны

Десктопное приложение (PyQt6) для формирования заключений по техническому
освидетельствованию баллонов-воздухохранителей высокого давления: оператор
вводит паспортные данные партии баллонов и результаты замеров, приложение
выполняет расчёты по ГОСТ (прочность, остаточный ресурс, овальность,
твёрдость) и рендерит готовый Word-документ по шаблону.

## Архитектура проекта

```
Voskresensk_ballons_pr/
├── main.py                        # Точка входа
├── requirements.txt                # Зависимости приложения (PyQt6, docxtpl)
├── requirements-dev.txt            # Зависимости для тестов (pytest)
├── pytest.ini
├── src/
│   ├── config.py                   # Пути, константы ГОСТ, поиск шаблона
│   ├── models/
│   │   └── project.py              # Project — сериализация сессии в JSON
│   ├── services/
│   │   ├── calculations.py         # Чистые функции расчётов (без Qt)
│   │   ├── formatting.py           # Форматирование под русскую запятую
│   │   ├── importer.py             # Импорт CSV/JSON
│   │   └── exporter.py             # Экспорт CSV/JSON
│   └── ui/
│       ├── main_window.py          # MainWindow — GUI и связка с сервисами
│       ├── widget_names.py         # Имена виджетов, резолвимых из .ui
│       ├── file_handler.py         # Qt-диалоги импорта/экспорта
│       └── designer/
│           └── main_window.ui      # Форма (Qt Designer)
├── tests/                          # Юнит-тесты src/services (без Qt)
├── templates/                      # Шаблоны Word с Jinja-плейсхолдерами (не в git)
└── output/                         # Сгенерированные документы (не в git)
```

Слои:
- **`src/services/calculations.py`** — единственный источник истины для формул
  ГОСТ. Чистые функции без зависимости от Qt: расчёт прочности, остаточного
  ресурса, генерация замеров толщины/овальности/твёрдости, поиск минимальной
  толщины и диапазона годов изготовления. У random-based функций источник
  случайности — внедряемый `random.Random`, что делает их детерминированно
  тестируемыми.
- **`src/services/formatting.py`** — форматирование чисел под русскую
  десятичную запятую (два раздельных паттерна: `format_ru` и
  `format_ru_fixed` — см. докстринг модуля, зачем они не взаимозаменяемы).
- **`src/services/importer.py` / `exporter.py`** — импорт/экспорт списка
  баллонов в CSV и сохранение/загрузка проекта в JSON.
- **`src/ui/main_window.py`** — `MainWindow`: резолвит виджеты из
  `main_window.ui` по спискам имён (`src/ui/widget_names.py`), обработчики
  кнопок читают форму, зовут чистые функции из `calculations.py`,
  форматируют результат и пишут в виджеты и в `self.data` — плоский словарь,
  который целиком уходит в `docxtpl` при рендере документа.

## Главный контракт

```
objectName виджета в main_window.ui  ==  ключ в self.data  ==  имя Jinja-плейсхолдера {{ ... }} в шаблоне .docx
```

Добавление нового поля в форму требует правки во всех трёх местах:
Qt Designer → `src/ui/widget_names.py` → шаблон `templates/Шаблон_финал.docx`.

## Обязательный порядок расчётов

Кнопки на вкладке «Расчёты» нужно нажимать в определённом порядке — каждый
следующий шаг использует данные предыдущего:

1. «Кол-во баллонов»
2. «Smin-min»
3. «Расчитать толщины»
4. «Расчёт на прочность»
5. «Остаточный ресурс»
6. «Расчёт овальности»
7. «Расчёт твёрдости»
8. «Выгрузить в Word»

Нарушение порядка не приводит к скрытой деградации: приложение показывает
предупреждение с указанием, какой шаг нужно выполнить сначала, а «Выгрузить
в Word» отказывается генерировать документ, пока не выполнены все 7
предыдущих шагов.

## Установка и запуск

```bash
pip install -r requirements.txt
python main.py
```

Запускать нужно из корня репозитория (там же лежит `output/`, куда
сохраняются документы).

## Тесты

```bash
pip install -r requirements-dev.txt
pytest tests/ -v
```

Тесты покрывают только `src/services/calculations.py` и `formatting.py`
(чистая бизнес-логика, без GUI) — 100% покрытие, не зависят от PyQt6/docxtpl.
GUI-слой тестами не покрыт — его поведение проверяется вручную запуском
приложения.

## Расчёты

Все формулы — в `src/services/calculations.py`:

- **Прочность** (`calculate_strength`) — расчётные напряжения и толщины по
  ГОСТ 34233.1, допустимое давление, ступени пневмоиспытания.
- **Остаточный ресурс** (`calculate_residual_life`) — скорость коррозии и
  оставшийся срок службы.
- **Толщины** (`generate_thickness_measurements`) — 20 замеров вокруг
  измеренного минимума; минимум сгенерированного списка всегда равен
  фактически измеренному значению.
- **Овальность** (`generate_ovalness_measurement(s)`) — 3 замера диаметра
  на баллон.
- **Твёрдость** (`calculate_hardness_range`, `generate_hardness_measurements`)
  — диапазон по ГОСТ на основе временного сопротивления Rm, введённого
  оператором.

Замеры толщин, диаметров и твёрдости синтезируются случайным образом вокруг
введённых оператором опорных значений — это осознанное рабочее поведение
приложения, а не заглушка.

## Импорт/экспорт данных

- **CSV** — список баллонов (`;`-разделитель, `utf-8-sig`, запятая как
  десятичный разделитель). Кнопки «Импорт CSV» / «Экспорт CSV».
- **JSON** — полное состояние сессии (`Project`): поля формы, таблица
  баллонов, настройки. Кнопки «Сохранить проект» / «Открыть проект».

Загрузка проекта восстанавливает значения виджетов и таблицу баллонов, но
не восстанавливает результаты расчётов — после «Открыть проект» кнопки
из раздела «Обязательный порядок расчётов» нужно нажать заново.
